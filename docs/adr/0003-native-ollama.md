# ADR 0003: Run Ollama natively on Windows

- **Status:** Accepted
- **Date:** 2026-11-13
- **Related:** FR-07, NFR-02, NFR-03, NFR-10; [ADR 0004](0004-full-gpu-offload.md); [environment.md](../environment.md)

## Context

Answers are generated by a locally running language model (FR-07), and the full flow must work offline after installation (NFR-02). The benchmark laptop has a GTX 1650 with 4 GB of VRAM. Ollama needs direct access to it through NVIDIA driver 550 or newer; the laptop runs 581.29.

Docker Desktop runs containers inside a WSL 2 Linux VM whose memory is capped at 6 GB. Generation speed on this GPU is sensitive to how the model is placed in memory (see ADR 0004). NFR-10 requires a new machine to reach a working UI by following the README.

## Decision

We will install Ollama natively on Windows and store its models on `D:\dev\ollama-models` through the `OLLAMA_MODELS` setting. The application reaches Ollama over HTTP at a configurable address:

- `localhost:11434` when the code runs on Windows during development
- `host.docker.internal:11434` when the code runs in a container. This path was verified on 2026-11-10 from a test container.

## Alternatives considered

- **Ollama in a Docker container with GPU passthrough.** Everything would live in Docker Compose, closer to a one-command setup. But it adds a GPU passthrough layer through WSL 2 to configure and debug, and puts model files and any CPU-side memory inside the 6 GB VM limit.
- **llama.cpp server directly.** The same inference engine Ollama uses underneath, with finer control, but manual model downloading and management.
- **vLLM.** Built for high-throughput serving on Linux servers with larger GPUs. Not practical on a 4 GB card.

## Consequences

**Positive:**

- Direct GPU access with no passthrough layer. Combined with ADR 0004, the answer model runs fully on the GPU at about 40 tokens per second.
- Simple model management (`ollama pull`, `ollama list`), with models stored on the `D:` drive.
- Model memory is outside the WSL 2 cap.
- Works offline once the models are downloaded (NFR-02).

**Negative:**

- Setup is not a single command. The README must explain how to install Ollama and pull the models, which makes NFR-10 harder to meet.
- The application depends on a service outside Docker Compose. If Ollama is not running, the API must return a clear 503 error.
- `host.docker.internal` is a Docker Desktop convenience. On Linux with Docker Engine, containers need extra configuration to reach the host.
- The repository cannot pin Ollama's version. The tested version (0.40.15) is recorded in environment.md instead.
- Ollama listens only on `localhost` by default. It must stay that way; exposing it to the network would let any device on the Wi-Fi use it.
